# 前端面试刷题器

一个单文件、零依赖、可离线使用的前端面试刷题工具。点按钮随机出新题，先自己想，再看提示和答案，最后逐条过面试官追问。

**85 题 · 257 条面试官追问**，覆盖 JS 基础、CSS、浏览器与网络、Vue/React、工程化、算法手写、概念理解七类，难度分基础 / 高频 / 进阶三档。

## 在线访问

部署到 GitHub Pages 后，访问地址为：

```
https://wangyaruo.github.io/learn-test/
```

入口页是仓库根目录的 `index.html`，点「开始刷题」进入 `interview-trainer.html`。

> 启用方式（仓库管理员操作一次即可）：Settings → General → 底部 Danger Zone → Change repository visibility 改为 Public；再到 Settings → Pages，Source 选「Deploy from a branch」，分支选 `main`、目录选 `/ (root)`，保存。首次发布可能需要几分钟。
>
> 注意：Pages 站点是**公开可访问**的，即使仓库保持私有也一样。私有仓库只保护源码，不会限制网站访问。

## 怎么用

直接双击 `index.html`（入口页）或 `interview-trainer.html`，用浏览器打开即可。不需要 Node、不需要 npm、不需要构建，断网也能用。

### 快捷键

| 按键 | 作用 |
|---|---|
| `空格` 或 `→` | 换一题 |
| `H` | 看提示 |
| `A` | 看答案 / 收起答案 |
| `F` | 展开 / 收起全部追问（需先看答案） |
| `S` | 收藏 / 取消收藏 |

### 三层渐进揭示

**提示 → 参考答案 → 面试官追问**，一层层展开，逼自己先想再看。

追问区默认只列出问题，点某一条才展开要点，也可以一键展开全部。这样设计的原因：真实面试是连环追问，只背主问题的答案是过不了的；而如果把要点和问题一起摊开，很容易扫一眼就当自己会了。

### 筛选

- **分类**：七类可任选
- **难度**：基础 / 高频 / 进阶
- **范围**：随机全部 / 只出没看过的 / 只看我的收藏
- **标签**：只列出**能跨题检索**的考点（在题库中出现 2 次以上）。题目上的细粒度标签（只对这一题有意义）也可以点，只是筛选结果可能只有一两题

进度与收藏保存在浏览器 localStorage，刷新不丢。右上角可切换深浅色主题，或重置进度。

## 怎么加题

打开 `interview-trainer.html`，找到 `const BANK = [`，按同样格式往数组里追加对象：

```js
{c:'js', lv:'高频',
 q:'题干写在这里',
 h:'提示写在这里',
 a:`<p>答案支持 HTML：<b>加粗</b>、<code>行内代码</code></p>
<pre><code>代码块直接写在 pre 里</code></pre>`,
 tags:['闭包','内存与垃圾回收'],
 fu:[{q:`追问：这里写面试官的第二层问题？`, a:`这里写要点，两三句话讲清就够了。`},
   {q:`追问：再下一层？`, a:`要点。`}]},
```

字段说明：

| 字段 | 含义 | 合法值 |
|---|---|---|
| `c` | 分类 | `js` `css` `net` `fw` `eng` `algo` `concept` |
| `lv` | 难度 | `基础` `高频` `进阶` |
| `q` | 题干 | 任意文本，**必须全局唯一** |
| `h` | 提示 | 只给思考方向，别把答案写进去 |
| `a` | 参考答案 | HTML 字符串 |
| `tags` | 考点标签 | 字符串数组，至少 1 个，同一题内不重复 |
| `fu` | 面试官追问 | 数组，每项 `{q: 问题, a: 要点}`，建议每题 2～3 条 |

### 三条硬性约束

1. **题干必须全局唯一。** 题干是收藏与进度的稳定键（代码里的 `keyOf`），重复会导致记录错位，校验脚本会直接报错。
2. **`a` 与 `fu` 的反引号内不能出现裸反引号。** 它们本身用模板字符串包裹，行内代码一律用 `<code>` 标签——否则模板字符串会提前终止，整个页面白屏。这是本项目真实踩过的坑。
3. **`tags` 与 `fu` 不能留空。** 校验脚本会逐条报出是第几题、哪个字段缺失。

### 关于标签的写法

标签分两种用途，写的时候心里要有数：

- **能跨题检索的**（如 `闭包`、`this`、`双指针`）：会出现在筛选区，点一下能筛出一组题，适合集中复习某个考点
- **只对这一题有意义的**（如 `IEEE754`、`TimSort`）：作为知识点标注显示在题目上，点它只会筛出这一题

标签的大小写要统一（`flex` 与 `Flex` 会被当成两个不同标签），校验脚本会对大小写不一致给出警告。

## 校验

改完题库后跑一次：

```bash
node scripts/check-bank.js
```

脚本会做三件事：

1. 编译页面里的整段脚本，抓语法错误（上面第 2 条约束就是靠这一步拦住的）
2. 解析题库，校验字段完整性、分类与难度合法性、题干唯一性
3. 校验 `tags` 与 `fu` 的结构：标签非空去重、追问含问题与要点、标签大小写一致性

有错误时退出码为 1，所以也能直接用于 CI。仓库已配置 GitHub Actions，push 后会自动运行。

也可以指定文件路径，用于校验校验器本身是否真的能拦住错误写法：

```bash
node scripts/check-bank.js ./某个改动过的副本.html
```

## 技术说明

- **为什么是单文件**：直接用 `file://` 打开时，浏览器会拦住外部 JS 模块的加载（跨域限制）。单文件是零依赖离线可用的最简方案。
- **持久化键为什么不用数组下标**：早期版本用下标做 id，在题目中间插入新题会让后面所有题的 id 后移，已存的收藏就会指向别的题。现在改用 `分类::题干` 作为稳定键。
- **旧数据迁移**：如果浏览器里存在旧版（v1，按下标存储）记录，首次打开新版本时会自动换算成稳定键，无需手动处理。
- **修改题干等于换钥匙**：改动某题题干会让该题的进度和收藏重置，这是预期行为。
- **筛选区为什么只列部分标签**：题库里有 200 多个标签，但绝大多数只对应一两道题。如果全列出来，点任何一个都只筛出一题，检索就没意义了。所以筛选区只展示真正能跨题检索的那些。
